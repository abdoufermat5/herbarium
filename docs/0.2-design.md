# Herbarium 0.2 — "Pages that keep working"

## Understanding summary

- 0.1.0 shipped: a vault of plain `.html` + `.json` sidecar files, sandboxed reader, search, fixed-ladder review, MCP server.
- 0.2 makes saved pages keep working over time and makes review adaptive.
- Scope: page storage (A1), page version history (A2), `herbarium add` CLI + deep links (B2), adaptive FSRS review (C1), signed builds + package-manager manifests (E1).
- No users yet: defaults may change without migration prompts, but sidecars written by 0.1 must keep loading.
- Non-goals: browser extension, page links/graph, thumbnails, sync, mobile, AI features, third-party plugin loader.

## Assumptions

- Single user per vault; "shared" `window.storage` keys are just a separate local namespace.
- Per-page state stays small (capped at 1 MiB serialized).
- Signing certificates and package-registry accounts do not exist yet; release jobs must skip cleanly without them.

## Decision log

| # | Decision | Alternatives | Why |
|---|---|---|---|
| 1 | Page state lives in the sidecar under `ext["storage"]` | separate `<id>.state.json`; SQLite | Moves, trash, restore and export already carry the sidecar; no new file kind for the vault to track. |
| 2 | Storage shim injected by `protocol.rs`, persisted through `postMessage` to the reader, page id taken from the reader, never from the message | `allow-same-origin` | Keeps the sandbox opaque-origin; the page cannot pick which page it writes to. |
| 3 | `storage.*` operations are UI-only | expose to agents | Page-written data is untrusted input; keeps it out of agent context. |
| 4 | Storage writes never change `updatedAt` and never count as an external edit | — | `updatedAt` is the HTML save-conflict token; a reload would wipe in-progress page state. |
| 5 | History snapshots in `.herbarium/history/<id>/`, newest 50 kept, taken before any in-app/agent HTML overwrite whose content differs | git; copy-on-every-save | Plain files, bounded disk use, covers the agent-overwrite risk. External disk edits are not snapshotted (not observable before the write). |
| 6 | `history.*` operations are visible to agents | UI-only | Lets an agent undo its own `set_html`. |
| 7 | Diff view with `@codemirror/merge` | custom diff | CodeMirror is already the editor. |
| 8 | OS deep-link scheme `herbarium-app://` | reuse `herbarium://` | `herbarium://` is the in-webview page protocol; a distinct scheme avoids ambiguity. |
| 9 | `herbarium add` runs in-process against the vault (like `herbarium mcp`); the running app picks changes up on focus | IPC to the running app | Reuses the existing external-change path; no IPC surface. |
| 10 | FSRS-6 scheduler with default parameters, implemented in-crate | `fsrs` crate | The crate pulls an ML training stack; scheduling alone is ~100 lines of formulas. |
| 11 | FSRS becomes the default strategy; grades become Again/Hard/Good/Easy (keys 1–4) | keep ladder default | No users yet; adaptive scheduling is the point of C1. Old `again`/`good` sidecars stay valid. |
| 12 | Windows signing, Homebrew, winget, AUR jobs gated on their secrets; Flatpak ships as a manifest for a manual Flathub submission | require secrets | Releases must keep working before accounts exist. |

## A1 — Page storage

- Data: `meta.ext["storage"] = { "local": {k: v}, "personal": {k: v}, "shared": {k: v} }`, string values; total ≤ 1 MiB; key ≤ 200 chars.
- Operations (UI-only): `storage.get {id}`, `storage.write {id, changes: [{area, key, value|null}]}`, `storage.clear {id}`.
- Shim (served page and draft preview): `localStorage` (persisted, area `local`), `sessionStorage` (memory only), `window.storage` `get/set/delete/list` with the Claude artifact signatures (areas `personal`/`shared`). Initial state is embedded in the shim; writes are batched to the parent. The draft preview never persists.
- Reader: validates `event.source`, debounces writes, flushes on page switch/close, offers "Reset page data".
- `window.storage` no longer triggers the "made for Claude" warning; `window.claude` still does.

## A2 — Version history

- Files: `.herbarium/history/<id>/<atMs>.<ui|agent>.html`, newest 50 kept.
- Operations: `history.list {id}`, `history.get {id, at}`, `history.restore {id, at, expectedUpdatedAt?}` (snapshots the current HTML first; same conflict rule as `set_html`).
- Lifecycle: survives move/trash/restore; deleted when the page is purged; a new page never inherits stale history for a reused id.
- Reader: History panel, side-by-side diff against the current HTML, Restore with confirmation and the unsaved-draft guard.

## B2 — CLI and deep links

- `herbarium add [--vault P] [--folder F] [--tag T]... [--title T] [--network|--no-network] <file|-|url>...`, vault resolved like `herbarium mcp`, imports through the same validation as the app, prints `<id>\therbarium-app://open/<id>` per page, non-zero exit if any input fails.
- `herbarium-app://open/<page-id>` opens the reader; `herbarium-app://review` opens Review. Single-instance forwarding to the running window.

## C1 — Adaptive review

- `Strategy::Fsrs` (default) with `desiredRetention` (0.70–0.97, default 0.90); per-page `stability`/`difficulty` in `ext["review"]`.
- Grades `again|hard|good|easy`. Again → first preset (relearning step). Non-FSRS strategies: Hard repeats the interval, Easy advances twice.
- `review.preview {id}` returns the interval each grade would give; session buttons show them; keys 1–4, `S` skip, `Esc` leave.

## E1 — Distribution

- Windows Authenticode signing from `WINDOWS_CERTIFICATE`/`WINDOWS_CERTIFICATE_PASSWORD`, skipped when absent.
- Homebrew cask (tap via `HOMEBREW_TAP_TOKEN`), winget (`WINGET_TOKEN`), AUR `herbarium-bin` (`AUR_SSH_PRIVATE_KEY`), Flatpak manifest + AppStream metainfo.
- Maintainer guide: `docs/distribution.md`.
